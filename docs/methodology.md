# From learning concepts to client delivery

The toolkit has two kinds of knowledge:

1. Durable methods: workflow discovery, evidence tracking, separate routing axes, minimum viable capability selection, source/access boundaries, evaluation, stage-specific readiness, and actionable handoff.
2. Changing implementation facts: model names, endpoints, product features, subscriptions, limits, hosting, agreements, and pricing.

The skill stores the first and instructs the assistant to verify the second when relevant. It does not turn a remembered product detail into a recommendation.

## Evidence rather than a questionnaire

The four discovery layers are lenses for spotting uncertainty. They are not an intake form to ask in full every time. The assistant should use information already supplied, prioritize unknowns that change the decision, and continue useful safe work.

A three-axis routing memo records a provisional choice, why it fits, an alternative, a change condition, and open evidence. A solution snapshot carries those decisions forward so a later blueprint, eval plan, or implementation task can reuse them.

## Planning and execution

The skill can produce a call brief, blueprint, or build task. If the user asks for implementation and the environment provides the tools and authorization, it should implement and validate the next scoped slice. Loading the skill does not itself authorize publication, business-system writes, credential creation, or deployment.

Unresolved production controls do not always block a synthetic prototype. Conversely, a demo is not release acceptance. Readiness is assessed for a named stage and a particular workflow, audience, data set, and action scope.

## Maintaining quality

Use synthetic behavioral cases to inspect whether the skill asks useful questions, preserves explicit constraints, distinguishes risk boundaries, and moves toward executable work. Review actual outputs with the rubric; do not infer quality from presence of headings or keywords. Track observed failures and make focused corrections.

The initial version has structural validation and installer tests plus a reproducible behavioral evaluation pack. It does not claim measured model performance or automated behavioral validation. Contributions should state what was actually run.
